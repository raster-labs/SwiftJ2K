# SwiftJ2K Phase R3 Capability, Specification & Independent Oracle Matrix

This document maps every advertised `SwiftJ2K3D` (ITU-T T.809 | ISO/IEC 15444-10 — JP3D, plus ITU-T T.801 | ISO/IEC 15444-2 Annex I/J reversible component bit-split for high-dynamic-range `34...38`-bit volumes), HT-in-JP3D (ITU-T T.814 | ISO/IEC 15444-15 reconciled with Part 10), and `SwiftJ2KJPIP` (ITU-T T.808 | ISO/IEC 15444-9 — JPIP, plus the non-ITU RFC 6455 WebSocket extension) mode, public library route, and `swiftj2k-cli` subcommand to its primary normative specification clauses, wire/codestream representation, independent peer coverage, and executed Phase R3 (`F01` and `F04`) verification receipts.

> **Verification Status & External-Peer Gate Convention**: Every verification entry links directly to raw executed receipts and SHA-256 digests under `Documentation/Engineering/Remediation/Evidence/R3/` (with historical pre-rework `2b2d79a1716fe55d40836fbcd4e7c50ed6bbb9f6` receipts preserved byte-for-byte under `Documentation/Engineering/Remediation/Evidence/R3/historical-2b2d79a/`). Capabilities where none of the locally available external reference peers (`OpenJPEG v2.4.0`/`v2.5.4`, `Kakadu v8.4.1`, `OpenJPH 0.30.1`) implements a direct peer endpoint — specifically **combined Part 10 `NSI` + Part 15 `Ccap^15` HT-in-JP3D**, **3D JPIP over Part 10 `NSI`**, and the **non-ITU RFC 6455 WebSocket JPIP binding** — are verified via protocol-derived harnesses, shared-encoder external 2D HT oracles (`kdu_expand`, `ojph_expand`), wavelet-domain transcode to `openjp3d`, and process-separated TCP endpoints, while their direct external third-party peer gates remain explicitly **`UNEXECUTED` and `UNWAIVED`**. Developer state is **`submitted`** (`Codex acceptance: pending independent audit`).

## 1. Pinned Primary Specifications & External Reference Peers

### 1.1 Normative Specifications Inspected
- **JP3D (Part 10)**: **ITU-T Rec. T.809 (05/2011) | ISO/IEC 15444-10:2011** (*Information technology — JPEG 2000 image coding system: Extensions for three-dimensional data*), complete 54-page primary text inspected directly (`https://www.itu.int/rec/dologin_pub.asp?id=T-REC-T.809-201105-I%21%21PDF-E&lang=e&type=items`).
- **HTJ2K (Part 15)**: **ITU-T Rec. T.814 (06/2019) | ISO/IEC 15444-15:2019** (*High-throughput JPEG 2000*), complete 80-page primary text inspected directly (`https://www.itu.int/rec/dologin_pub.asp?id=T-REC-T.814-201906-I%21%21PDF-E&lang=e&type=items`).
- **Extensions (Part 2)**: **ITU-T Rec. T.801 | ISO/IEC 15444-2** Annex A (`CBD` `0xFF78`, `MCT` `0xFF74`, `MCC` `0xFF75`, `MCO` `0xFF77`) and Annex I/J multi-component reversible linear recombination (`19 + (B - 19)` component bit-split when `34...38`-bit 3D wavelet coefficients reach `|coeff| >= 2^37`).
- **Core Coding System (Part 1)**: **ITU-T Rec. T.800 (06/2019) | ISO/IEC 15444-1:2019** (including Annex F whole-sample symmetric wavelet boundary extension `PWS`).
- **JPIP (Part 9)**: **ITU-T Rec. T.808 (12/2022) V2 | ISO/IEC 15444-9** (*Interactivity tools, APIs and protocols*, primary PDF `https://www.itu.int/rec/dologin_pub.asp?id=T-REC-T.808-202212-I%21%21PDF-E&lang=e&type=items` and formal ABNF request grammar `https://www.itu.int/ITU-T/formal-language/itu-t/t/t808/2022/JPIP%20Request.html`), cross-checked against OpenJPEG `v2.4.0` `libopenjpip` (`msgqueue_manager.c`, `jp2k_encoder.c`, `j2kheader_manager.c`, `jpip_parser.c`, `cachemodel_manager.c`) and live Kakadu `kdu_server` `v8.4.1` wire captures.
  - *Edition & Access Disclosure*: The official ITU listing (`https://www.itu.int/rec/T-REC-T.808/en`) marks **ITU-T Rec. T.808 (06/2026) V3** (which adds HTTP/3 Annex P and `h3`/`h3s` channel types) as in force/prepublished, while its full text is TIES-restricted and unavailable publicly; `SwiftJ2KJPIP` explicitly pins **ITU-T Rec. T.808 (12/2022) V2** (HTTP/1.1 over TCP per Annex F) and deterministically rejects T.808 V3 / HTTP/3 with `CodecError(.unsupportedFeature, ...)`.
- **WebSocket Extension**: **IETF RFC 6455** (*The WebSocket Protocol*). WebSocket transport in `SwiftJ2KJPIP` is an explicit repository / `API-13` extension carrying normative Annex A JPIP messages and query payloads over RFC 6455 frames, not an ITU-T T.808 transport binding.
