C1 — P1: Continued codeword segments allocate a full COW replacement after admitting only the suffix
-------------------------------------------------------------------------------------------------
Primary location: Sources/SwiftJ2K3D/JP3DTier12Coder.swift:3638–3644.
Ownership evidence: local outSt copies result[c][r][p][band][block] at3600; result retains its old segment until the assignment at3654. Appending to outSt.segments[last].data therefore detaches shared array storage when an existing segment is continued. The admitted delta is only length for nonempty data, omitting the complete previously retained segment during replacement. appendEmptySegment at3375–3377 has the analogous retained-segment-array capacity/COW issue for successive terminated segments.

Concrete trigger: tiny 1x1x1 EBCOT tile, two retained quality layers for one unterminated codeword segment, a large first contribution A (e.g.1MiB) and a short second contribution B. Packet header Lblock can encode these lengths. Before Tier-1 validity is examined, layer2 can allocate A+B while the original A remains live; admission charges only B on top of A. Set remaining worker allowance between A+small geometry and 2A. This is an input-caused pre-allocation-limit violation regardless of whether the later entropy decode accepts the payload. The small fixed block scratch/geometry allowance cannot cover an arbitrarily large declared compressed contribution. Whole decode, ROI, coefficient transcode and indexer share this parser.

This is confirmed from source ownership and allocation order; no native reproducer was run by this auditor. A useful native regression must observe the continuation allocation, not just eventual resourceLimitExceeded. Fix by moving out the retained segment before unique mutation and charging actual replacement/growth overlap/capacity, or by reserving that overlap explicitly before append. Preserve malformed-input rejection and cancellation.

C2 — P1: 3D indexing admits only one tile-body staging copy but the new forwarding overload allocates another
------------------------------------------------------------------------------------------------------------
Primary locations: Sources/SwiftJ2K3D/JP3DTier12Coder.swift:3303–3307; Sources/SwiftJ2K3D/JP3DJPIPIndexer.swift:251–264,319–329.

The indexer retains tileBitstream:[UInt8], charges bitstreamBytesCount once at252, then calls decodePackets(bytes:tileBitstream). The new bytes overload immediately constructs Data(bytes) at3307 and holds it through packet parsing. This allocates a second complete tile body before admitWorkspaceBytes is called. The array input remains needed at347 to copy indexed packet slices. Thus the additional Data is a concrete unadmitted overlap, even if every later packet callback is denied.

Concrete trigger: a large Part10 tile body under a workspace cap that admits retained tile data, one bitstream staging array and geometry but not an additional tile-sized Data. The conversion occurs before the first dynamic packet admission, exceeding the cap before rejection. Use the Data overload directly from an admitted Data owner, eliminate the conversion, or reserve and retain the duplicate-buffer lease before creating it.

Related existing aggregate omission in this same indexer: parse(data,limits:) at96 retains parsed tile payloads, [UInt8](data) at97 copies the entire input, and rawPartsByTile/allTiles live at the same time. Yet the indexer's wsCap at207 and retainedIndexBytes initialized to mainHeader.count at208 do not reserve any of these live owners. The parser's checks are separate and do not deduct its retained allocations from this next stage. At minimum source input, retained parsed payloads, whole-input array and indexer-owned staging must be reconciled in one live-memory admission. The precise new forwarding-copy regression above is independently sufficient; this paragraph does not claim measured process RSS.

Narrow repair assessment

RA2-02: Production whole/ROI/transcode packet traversal now streams addresses. LRCP/RLCP have no layer-dependent sequence array; spatial modes retain only a precinct-sized visited table and request its admission. Optional packet-range retention is explicit. Encoder per-block layer arrays are now counted in geometry. This removes the previous confirmed eager65535-layer sequence defect in source; C1/C2 remain distinct resource issues.

RA2-03 / F01-05: Signed20-bit low limb and signed high limb coding removes the old hidden unsigned DC offsets. Normative decode context disables Part1 shift/clamp before Part2 synthesis for whole and ROI decode. Reconstruction applies descriptor coefficients directly into final sample Data; transcode retains the synthesis marker group and coefficient semantics. No new confirmed arithmetic/marker mismatch was found in this bounded review.

Marker builder/parser agree on Xmcc=1, Nmcc/Mmcc bit15 index widths, CBD count mask0x7fff, Rsiz0xc100 and CODMCT2. Builder rejects single-segment overlength before UInt16 conversion and handles128/129 and256/257 index boundaries. MCC collection reads are segment-bounded. The rectangular irreversible2->1 array is legal; the withdrawn rectangular objection is not reinstated. New index-boundary tests currently round-trip marker parsing; external normative/semantic qualification remains mandatory.

Further bounded verification, not additional confirmed findings
--------------------------------------------------------------
- HT SigProp-only output at HTBlockCoder.swift:1195–1208 transfers spBytes to the caller while its scratch reservation is released by defer and only count is reserved as output. The returned buffer may retain the requested64-byte chunk capacity. Unlike MQ/raw finish, this branch does not compact. This is a bookkeeping/capacity concern worth closing or demonstrating covered by the block scratch bound; I have not established an end-to-end cap violation from this bounded<=63-byte tail alone, so do not count it as a separate confirmed P1.
- MQ/raw/HT growth now calls reserveCapacity in64-byte increments on budgeted paths, with multiple locking/telemetry calls per chunk. Byte-writing logic was largely preserved, but this is a hot-path allocation-policy change. Required controlled release benchmarks and byte comparisons must assess it; no runtime regression percentage or byte parity is claimed from source inspection.
- New derived Kakadu tests preserve tile/packet/entropy bytes while adapting dimensional headers and compare retained expected samples. They are useful narrow integration evidence after execution. They do not constitute a direct combined Part10+15 peer, and nominal multilayer fixtures do not alone prove every refinement/MULTIHT branch executed.
- Resource tests currently cover header denial, raw compaction, huge encoder layer metadata and optional verification accounting. They do not cover C1 continuation COW, C2 forwarding copies, or independent allocator-observed peak. Allocation telemetry records logical requested allocation at instrumentation sites; it is not a general allocator oracle.
