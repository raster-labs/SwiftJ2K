Process, pipe and continuation lifetime

run at 63–78 uses a checked continuation and a dedicated thread for launch/wait work. No global Dispatch queue or cooperative worker performs the blocking subprocess operations. The invocation retains owning argument/input values; no borrowed pointer escapes to a thread.

runBlocking at 81–140 constructs Process and pipes locally. If resolving or launching fails, the throwing path resumes the continuation once and the installed defer closes the handles. After successful launch, the parent's unused stdout/stderr writing ends and optional stdin reading end close at 101–103. Dedicated reader threads concurrently drain stdout and stderr at 110–121. Optional stdin has a separate writer, records any write failure, and closes its end before leaving the group at 122–132. This removes the old dependency cycle where the parent waits for stdout EOF while the child cannot finish writing a full stderr pipe.

The dedicated parent thread waits for child exit and the I/O group at 134–135 before reading results or propagating an input error. Output Data is transferred through Mutex; handles remain owned until all I/O finishes, and final defer closes them. Every group entry has a deferred leave; no continuation resumes before child exit and all registered I/O work complete. Process status/reason and stdout/stderr text conversion retain their existing meanings. No new unchecked Sendable annotation is added by this helper.

No new concrete lock-order, pipe-order or ownership deadlock was found for the tested finite child processes. As before, the helper relies on the child terminating and closing its pipe descriptors: it does not introduce a process-kill deadline or cancellation handler. That existing limitation is not a new timeout masking mechanism; CLI resource/deadline command arguments and all JPIP elapsed checks remain unchanged. The native campaign's outer execution bound remains relevant to a truly hung child.

The new 256 KiB dual-pipe/input regression at 172–184 deliberately makes the child fill stderr before reading stdin or producing stdout. It verifies exact output on both channels, normal termination, and the complete input echo. This meaningfully detects sequential-drain deadlock and premature return. It uses /bin/sh and standard shell/cat behavior on the existing Darwin/Linux host test platforms, with no product dependency on a shell.
