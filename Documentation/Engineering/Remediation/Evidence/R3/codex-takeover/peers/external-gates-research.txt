Part 2 synthesis: proposed narrow route; subsequent peer crash preserved
-----------------------------------------------------------------------
Local primary documentation:
/Library/Kakadu/8.4.1/Overview.txt:3485 says all Part 2 multi-component
transforms are supported. Lines 3502–3519 limit decoding to the first 30
magnitude planes and warn reversibly compressed >=30-bit samples may fail.
/Library/Kakadu/8.4.1/Usage_Examples.txt:750–845 documents matrix, offset,
Sprecision versus Mprecision, and fewer output than coded components.
Lines 2956–2963 document -codestream_components to bypass inverse MCT.

Read-only strings from the installed kdu_expand confirm concrete writer
limits: PGX and RAW reject >4 bytes/sample, TIFF rejects >32 bits/sample,
PFM holds 32-bit floats only. -fprec aligns/truncates/scales values; it cannot
establish a full38 exact sample oracle. -precise does not promise 64-bit
integer or double MCT processing. Do not claim full38 parity from these modes.

Prepared bounded test-only harness: work/independent-part2-peer.py. It has
NOT BEEN EXECUTED. It accepts --input emitted.jp3d --expected original.json
--output-dir NEW_DIRECTORY, optionally --kdu and --timeout1..60seconds.
JSON supplies width,height,bitDepth,signed,samples (exact integer array).
The diagnostic requires depth=1, NLz=0, zcb=0, equal reversible XY levels,
one origin-zero tile/part, no overrides/POC/explicit precincts, LRCP, signed
wire limbs <=20bits, and a single transmitted [1,524288] int32 array.
It independently validates CBD/MCT/MCC/MCO and normative Part2 signalling.
It removes NSI and only Part10 CAP, retains Part2/15 CAP words when present, converts COD
to2D, and retains all Part2 markers and the SOT/SOD/entropy/EOC bytes exactly.
Because there is no tile-header edit, Psot is unchanged and verified.
The adapted Rsiz is0xc100 with remaining CAP, or0x8100 without CAP.
Optional CPF is parsed and recorded, then omitted from the derived fixture:
this diagnostic does not assert the original corresponding-profile claim.
The harness calls installed kdu_expand once with -codestream_components,
-precise,-fussy,-num_threads0,-record and one signed PGX per wire component.
It independently parses PGX signedness, precision and endian order, applies
the transmitted array with exact integers, then compares every logical sample
and retains all source/tool/entropy hashes and logs. Native execution is
owned and serialized by root; no result is implied by writing this harness.

For full-range algebra, independently decode the <=20-bit signed limb planes
using -codestream_components and interpret the transmitted matrix and offsets
with an independent exact-integer Annex J implementation. This usefully checks
RA2-03 arithmetic and signalled conventions, but is a composite diagnostic;
it is not a direct independent full Part2+Part10 peer or full38 Kakadu output.

Part2 normative issues found while designing the independent harness
--------------------------------------------------------------------
Primary: ITU-T T.801 (V3) (08/2023), official publicly indexed epublication:
https://www.itu.int/epublications/publication/itu-t-t-801-v3-2023-08-information-technology-jpeg-2000-image-coding-system-extensions
Direct web open returned empty content, while the search index returned
the relevant tables and Annex A/J text. Reproducible search queries:
  site.itu.int/epublications "T.801" "reserved" "r" "Xmcc"
  site.itu.int/epublications "T.801" "Nmcc" "most significant"
  site.itu.int/epublications/publication/itu-t-t-801-v3-2023-08 "Extended capabilities"
Table A.35 represents array decorrelation as rrrrrr01; Annex A requires
reserved r bits0. Thus Xmcc0x09 is invalid reserved signalling; use0x01.
Tables A.36/A.37 put index width in bit15 of Nmcc/Mmcc:0=8bits,1=16bits.
The remaining count uses mask0x7fff, permitted1..16384; indices max16383.
Table A.30 similarly requires Ncbd&0x7fff, since0x3fff loses count16384.
Table A.38 assigns Tmcc low8 matrix, next8 offset, bit16 reversibility.
Table A.2 combines Part2 MCT + CAP as Rsiz0xc100; Table A.8 uses COD MCT2
for array processing. These fields must be correct in the original stream;
the harness refuses to silently repair them in the dimensional adaptation.
Annex J suppresses ordinary DC shift when its transform processing applies.

The official current recommendation page identifies2023 as in-force but its
download requires payment. No purchase/access circumvention was attempted:
https://www.itu.int/rec/T-REC-T.801/en
Official older2002 PDF (for historical comparison only):
https://www.itu.int/rec/dologin_pub.asp?id=T-REC-T.801-200208-S%21%21PDF-E&lang=e&type=items

Additional profile signalling concern: current JP3DHTMarkers.cpfMarkerData
uses Pcpf0x8000/0x8001 as lossless/lossy flags. Official T.814 A.6 instead
defines Pcpf as base65536 digits of CPFnum+1. Thus0x8000 means profile32767,
not reversibility. CPF is optional and makes a corresponding-profile claim;
production should omit an unestablished claim or supply a demonstrated one.
Primary: https://www.itu.int/rec/dologin_pub.asp?id=T-REC-T.814-201906-I%21%21PDF-E&lang=e&type=items
Search: site.itu.int "T.814" "CPF" "Pcpf"
