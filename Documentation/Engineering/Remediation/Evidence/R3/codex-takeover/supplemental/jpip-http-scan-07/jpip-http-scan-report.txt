Confirmed path
The previous header loop began scanning at readOffset after every one-byte
fill. An n-byte block therefore revisited its prefix quadratically. The chunk
line loop used the same shape. Parent reported the 2,000-header handshake
case took about 12 seconds normally and 25 seconds under ASan; those are
parent-owned observations, not measurements by this implementer. This repair
does not claim every prior EOF or elapsed failure came from that scan.

Repair and invariant
Line scanning now remembers the first unexamined index; each line byte is
visited exactly once. Header scanning remembers the previous buffer end minus
three bytes, clamped to readOffset. Only those final three positions could
begin an incomplete four-byte CRLFCRLF delimiter; LF-LF is covered too. Each
new byte adds at most four candidate-position visits. readOffset and indices
remain stable while awaiting more bytes; compaction still happens only after
a complete line/block is consumed. Existing first-match order, CR stripping,
search-before-cap order, immediate/partial EOF distinctions and all cap/error
conditions remain unchanged. fillOnceLocked still reads at most one byte for
these helpers, so there is no speculative body read or larger allocation.
Body/header storage admission and all timeout values are untouched.

Evidence
Package-only saturating counters under readLock record actual candidate
positions and line-byte visits. They cannot wrap under long-lived traffic.
Six new tests cover CRLF/LF delimiters at every final fragment boundary and
subsequent body/sentinel bytes; 1 KiB, 4 KiB and 16 KiB header values under a
4*n work bound; exact one-visit line counts for increasing chunk extensions
and trailers; a 2,000-header101 block under the same bound; accepted/denied
line and header caps before absent-body reads; and immediate versus truncated
EOF. Test socket reads/writes use dedicated workers with asynchronous completion
acknowledgement, so larger fixtures do not block a cooperative test worker
while pre-writing into a full socket. There are no elapsed-time assertions in
these algorithm-work regressions and no existing timeout/assertion was raised.
